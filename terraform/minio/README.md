# RustFS

OpenTofu configuration for the RustFS S3 server on node1, through the MinIO-compatible `aminueza/minio` provider.

| Files | Become |
|---|---|
| `resources/buckets/*.json` | buckets (versioning, object lock) |
| `resources/policies/*.json` | IAM policies |
| `resources/users/*.json` | users, with their policies attached |

One user, one policy and one bucket per service:

| Service | User | Bucket |
|---|---|---|
| Longhorn backups | `longhorn` | `k3s-longhorn` |
| Velero | `velero` | `k3s-velero` |
| k3s etcd snapshots | `etcd` | `k3s-etcd` |
| Node backups (restic) | `restic` | `restic` |
| Loki | `loki` | `k3s-loki` |
| Tempo | `tempo` | `k3s-tempo` |

```json
{ "access_key": "loki", "policies": ["loki"], "description": "Loki S3 user" }
```

Each user's secret key comes from Vault (`secret/s3/<user>`, generated by `terraform/vault`), so every password has one source. The module reads it with the `vault_kv_secret_v2` data source, which the Vault provider marks deprecated: the MinIO provider cannot take ephemeral values yet, so `tofu validate` prints a warning.

Buckets have `force_destroy`: removing a bucket file deletes the bucket and its objects at the next apply.

## Run

```shell
make configure-minio
```

Validate without RustFS:

```shell
./ansible-runner/ansible-runner.sh bash -lc 'cd /terraform/minio && tofu init -backend=false -input=false && tofu validate && tofu fmt -check'
```

The state (`terraform.tfstate`) stays on the control host and is not in Git.
